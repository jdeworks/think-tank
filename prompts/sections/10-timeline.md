# Section: Timeline & Milestones

> **Adapt to the project type.** For one-time launches: phases with deliverables.
> For recurring projects (events, services): cadence, prep cycle, and iteration plan.

## What to Capture
- Phases (what gets done in what order, with duration and deliverables)
- Milestones (key dates or checkpoints)
- For recurring projects: cadence (weekly, monthly, quarterly) and prep timeline per cycle

## Questions to Ask

### For all projects:
1. When do you want this to be ready?
2. What's the absolute minimum you need for the first version or first event?
3. What can wait until after the first version/event?

### For one-time launches (add):
4. What are the major phases? (Research, build, test, launch)
5. Are there hard deadlines or dependencies? (Conference date, funding deadline, seasonal window)

### For recurring projects (add):
4. How often will this happen? (Weekly, monthly, quarterly)
5. What's the prep timeline for each occurrence? (How far in advance do you need to start?)
6. What changes between iterations? (Speakers, menu, inventory, content)

## Quality Tips
- Projects always take longer than expected. Add 50% buffer to your estimates.
- The first version should be the smallest useful thing — not the complete vision.
- Set a date for the first version/event and work backward — what must be done by when?
- For recurring projects: plan the first 3 iterations, not just the first one.
- Milestones should have specific deliverables, not just dates.

## Common Mistakes
- No phases — just one big "do everything" block
- Deadlines without deliverables ("done by March" — done with WHAT?)
- Not accounting for dependencies (X can't start until Y is finished)
- For recurring projects: planning only the first event with no iteration plan
- Underestimating prep time for non-building tasks (permits, hiring, approvals)
