# Section: Project Overview

## What to Capture
- Project name
- One-sentence description
- Problem statement (what pain does this solve?)
- Goals (3-5 specific, measurable outcomes)
- Non-goals (what this project deliberately does NOT do)
- Target users (be specific — not "everyone")
- Success metrics (how do you know it's working?)

## Questions to Ask
1. Can you describe your idea in one sentence? What does it DO?
2. What problem does this solve? What's the pain point today?
3. Who specifically would use this? (Age, role, technical skill level?)
4. What does success look like 6 months after launch?
5. What is this project NOT? (Defining boundaries early saves time later)

## Quality Tips
- A vague description means a vague product. Push for specificity.
- "Everyone" is not a target user. The best products serve a specific niche first.
- Non-goals are as important as goals — they prevent scope creep.
- Success metrics should be measurable: "100 daily active users" not "people like it."
- If the user can't explain it in one sentence, the idea needs sharpening.

## Common Mistakes
- Skipping non-goals (leads to feature creep later)
- Setting goals that can't be measured
- Targeting too broad an audience
- Confusing features with goals ("add dark mode" is a feature, not a goal)
