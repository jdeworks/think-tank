# Section: Project Overview

## What to Capture
- Project name
- One-sentence description
- Problem statement (what pain does this solve?)
- Goals (3-5 specific, measurable outcomes — achievable by the primary user from Section 00)
- Non-goals (what this project deliberately does NOT do)
- Success metrics (observable actions, not feelings — tied to the primary user's first success)

## Questions to Ask
1. Can you describe your idea in one sentence? What does it DO?
2. What problem does this solve? What's the pain point today?
3. Given the primary user we defined, what does success look like 6 months after launch? (Use concrete numbers or observable outcomes.)
4. What is this project NOT? (Defining boundaries early saves time later.)

## Quality Tips
- A vague description means a vague product. Push for specificity.
- Non-goals are as important as goals — they prevent scope creep.
- Success metrics should be observable: "100 daily active users" or "first purchase within 10 minutes", not "people like it."
- If the user can't explain it in one sentence, the idea needs sharpening.
- Goals should be achievable by the primary user defined in Section 00 — if they aren't, either the goals or the primary user need revisiting.

## Common Mistakes
- Skipping non-goals (leads to feature creep later)
- Setting goals that can't be measured
- Confusing features with goals ("add dark mode" is a feature, not a goal)
- Writing success metrics as feelings instead of actions
